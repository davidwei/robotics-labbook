# Development

Use for ideation, implementation, simulation, and debugging away from physical hardware.

1. Identify the active project and experiment/question.
2. Retrieve relevant prior findings, decisions, failures, and unresolved questions.
3. Develop and simulate aggressively; physical robot time is constrained.
4. Record assumptions that simulation cannot validate.
5. For changes intended for physical validation, state expected behavior and failure modes.
6. Leave explicit questions for the next pre-lab plan.

Do not create physical-run records for ordinary development/simulation unless they are genuinely useful as experimental evidence.
