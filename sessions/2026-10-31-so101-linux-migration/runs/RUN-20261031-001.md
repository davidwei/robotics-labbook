# RUN-20261031-001 — native Linux SO101 teleoperation reproduction

The released SO101 migration package was installed on Ubuntu 24.04.5 LTS x86_64 at the exact source revision `bd49580152521e054218c1f41dd5b9bfeacc3d75`. Both arms and both cameras were reachable. After fresh full follower and leader calibration and a close-pose alignment check, the operator explicitly authorized a camera-free 20-second teleoperation run at 10 Hz.

The run connected both arms, completed its full interval and disconnected cleanly. Capture reported 200 submitted, 200 written and zero dropped samples. The operator reported: "the teleops works." Eight samples exceeded the configured 10-degree joint-error threshold. The maximum was 16.396 degrees on shoulder lift; other warning maxima were on shoulder pan, elbow and wrist flex. This supports successful functional teleoperation with transient tracking lag. It does not establish exact recovery time, collision margin, camera recording, replay, or long-duration reliability.

The post-run read-only check found both calibration records matched motor registers, all motor statuses were zero, and torque was disabled. No further motion was performed.

The analysis tool overwrote the original raw JSONL because the input filename did not use its required `.telemetry.jsonl` suffix. The console, capture summary, eight-event report and CSV remain available under `../evidence-linux/`; original per-sample telemetry does not. One constant-speed catch-up projection was produced, but it is not a measured recovery time and is not used for the pass decision.
